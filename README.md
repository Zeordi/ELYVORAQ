Development Principles

The project should follow these rules:

Reusable Components

Build reusable components instead of duplicating UI.

Design Tokens

Centralize:

- Colors
- Typography
- Spacing
- Radius
- Shadows
- Motion
- Breakpoints

Consistency

All pages must use the same visual language.

No Duplicate Pages

Before creating a new page or component:

1. Inspect the existing project.
2. Determine whether the functionality already exists.
3. Reuse or extend the existing implementation.
4. Only create a new component when genuinely necessary.

Production Quality

Code should be:

- Maintainable
- Modular
- Accessible
- Responsive
- Performant
- Type-safe where applicable
- Easy to extend

Development Workflow

1. Clone

git clone <repository-url>
cd <repository-folder>

2. Install Dependencies

Use the package manager already defined by the repository.

For example:

npm install

or:

pnpm install

or:

yarn install

---

3. Environment Variables

Create a local environment file when required:

.env.local

Never commit private credentials.

Example:

NEXT_PUBLIC_SITE_URL=
NEXT_PUBLIC_API_URL=

Only add variables that are actually required by the application.

---

4. Run Development Server

For an npm-based project:

npm run dev

Then open the local development URL shown by the framework.

---

5. Production Build

npm run build

---

6. Production Preview

Use the framework's appropriate production command, for example:

npm run start

---
